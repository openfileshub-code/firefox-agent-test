# Firefox/Camoufox Browser Agent — рабочий протокол

## 1. Цель и главные правила

Этот скилл применяется при работе с Firefox/Camoufox MCP.

Приоритеты:

1. Выполнить прямой запрос пользователя.
2. Проверить результат достаточным, но минимальным способом.
3. Не делать лишних проверок, не отправлять промежуточные сообщения.
4. Не повторять действия с возможными побочными эффектами вслепую.
5. Не утверждать то, чего инструменты не подтвердили.

### Правило одного хода

Если пользователь просит выполнить простое действие — например, «открой YouTube», — выполни все необходимые вызовы MCP **в рамках одного хода агента**, затем кратко сообщи результат.

Не разбивай одну задачу на отдельные сообщения:

- не сообщай сначала, что «проверяешь браузер»;
- не спрашивай разрешение на обычную навигацию;
- не вызывай диагностические инструменты без необходимости;
- не останавливайся после подключения MCP, если пользователь просил открыть сайт.

Если соединение уже доступно — сразу вызови `browser_navigate`.

Если инструмент сообщает, что MCP-клиент не подключён, вызови `browser_start`, затем сразу продолжи исходную задачу. Не отправляй между этими вызовами сообщение пользователю.

Если сайт уже открыт в нужной вкладке, не открывай его заново без необходимости.

### Жёсткая политика вкладок

1. **Работай только в первой (текущей) открытой вкладке.** Все переходы по сайтам, навигация, поиск и взаимодействие с интерфейсом выполняются через `browser_navigate` в текущей вкладке, если пользователь явно не потребовал открыть новую вкладку или новое окно.
2. **Не создавай новые вкладки без прямого указания.** Вызов `browser_new_tab` допускается исключительно тогда, когда пользователь явно попросил «открой в новой вкладке» или аналогичным образом указал на необходимость новой вкладки.
3. **Никогда не плоди новые окна браузера.** Если пользователь запросил открытие новой вкладки, она должна быть создана строго в том же окне, где уже открыта первая (основная) вкладка. Не запускай отдельные процессы или окна для новых задач.
4. **Возвращайся к исходной вкладке при потере контекста.** Если по какой-то причине была создана новая вкладка вопреки правилам, немедленно закрой её через `browser_close_tab` и переключись обратно на основную через `browser_switch_tab`, после чего продолжи работу там.
5. **Запрещено использовать `browser_new_tab` как способ «обновить» страницу или сбросить состояние.** Для возврата на главную страницу сайта используй `browser_navigate` в текущей вкладке.

### Не имитируй отсутствующие инструменты

Вызывай только те инструменты, которые реально присутствуют в текущем списке MCP-инструментов.

Не придумывай названия инструментов и не делай вид, что недоступная функция выполнилась.

## 2. Доступные инструменты и их фактический смысл

Основные инструменты текущего проекта:

| Инструмент | Назначение |
|---|---|
| `browser_start` | Подключиться к отдельно запущенному демону браузера. Не открывает сайт. |
| `browser_stop` | Явно остановить браузер и демон. Не вызывать без прямой просьбы пользователя. |
| `browser_navigate(url, new_tab=False)` | Перейти по URL в текущей вкладке или создать новую вкладку. |
| `browser_new_tab(url="")` | Создать вкладку; при наличии URL открыть его в новой вкладке. |
| `browser_tabs` | Получить перечень вкладок. Вызывать, если нужно выбрать или проверить вкладку. |
| `browser_switch_tab(index)` | Переключиться по индексу вкладки. Индексы могут измениться после закрытия вкладок. |
| `browser_close_tab(index=-1)` | Закрыть вкладку. |
| `browser_click_text(text, index=0)` | Найти текст на странице и нажать выбранное совпадение. Не гарантирует поиск по одному только `aria-label`. |
| `browser_press_key(key)` | Нажать клавишу, например `Enter` или `Escape`. |
| `browser_type_text(selector, text, clear=True)` | Заполнить поле по CSS-селектору. Используй только селектор, найденный на странице или известный из надёжного контекста. |
| `browser_scroll(direction, amount)` | Прокрутить страницу на заданное число пикселей. |
| `browser_get_content(max_chars=8000, mode="text")` | Получить текст или HTML страницы. Используй для проверки содержимого, а не автоматически после каждого действия. |
| `browser_screenshot(full_page=False)` | Сделать снимок страницы, если он нужен для задачи или если текстовых данных недостаточно. |
| `browser_search_on_page(pattern, regex=False)` | Найти текст на текущей странице. Это **не** поисковая строка сайта и не интернет-поиск. |
| `browser_find_link(pattern="")` | Найти ссылки и интерактивные элементы на текущей странице по примерному текстовому совпадению. Возвращает ранжированных `candidates` (`candidate_id/text/href/video_id/score`); при низком confidence — `NO_CONFIDENT_MATCH_ON_CURRENT_PAGE`. |
| `browser_video(action, value=None)` | Выполнить поддерживаемое действие с HTML5-видео и получить результат. Принимает также `target`, `expected_video_id`, `verify`, `override_phrase`. Полный список действий — в разделе «Видео» ниже. |
| `browser_expand_menu(trigger_text)` | Раскрыть меню/бургер перед кликом по скрытому элементу. Обязательный шаг вместо прокрутки или слепого повтора клика. |
| `browser_go_back` / `browser_history_back` | Нативная кнопка «Назад» браузера. |
| `browser_go_forward` | Нативная кнопка «Вперёд» браузера. |
| `browser_click_selector(selector)` | Нажатие элемента по подтверждённому CSS-селектору. |
| `browser_get_context` | Получить текущий контекст страницы: URL, сайт, `video_id`, `list_id`, `index`, `is_radio`, layout плеера. Вызывай после отказа guard'а и перед действиями с видео. |
| `browser_validate_url(url)` | Проверить URL на placeholder / невалидный video_id до навигации. |
| `browser_reload_settings(path="")` | Перечитать `user_tool_settings.json` без перезапуска демона. |

Следующие инструменты относятся к расширенной версии и доступны **только если они действительно зарегистрированы в MCP-хосте**:

| Инструмент расширенной версии | Назначение |
|---|---|
| `browser_inspect_page(include_frames=True)` | Инвентаризация интерактивных элементов и доступных iframe. |
| `browser_search_text(query, include_frames=True, limit=30)` | Поиск текстового совпадения, в том числе в доступных iframe. |
| `browser_scroll_to_text(text)` | Прокрутка к найденному тексту. |
| `browser_click_selector(selector)` | Нажатие элемента по подтверждённому селектору с проверкой видимости и доступности. |
| `browser_form_inspect()` | Просмотр полей формы и признаков возможной капчи. |
| `browser_form_fill(values)` | Заполнение найденных полей. Само по себе не отправляет форму. |
| `browser_websocket_events(limit=50)` | Метаданные WebSocket-событий, без содержимого кадров. |
| `browser_network_errors()` | Сетевые ошибки и HTTP-ответы 4xx/5xx, если инструмент зарегистрирован. |
| `browser_dialog_state()` | Проверка наличия ожидающего браузерного диалога, если зарегистрирован. |
| `browser_dialog_resolve(action, prompt_text="")` | Ответ на диалог после явного решения пользователя, если зарегистрирован. |

`browser_eval` — выполнение JavaScript в странице. Это мощная функция, но не используй её вместо готовых инструментов. Не применяй её для управления видео, заполнения неизвестных полей, обхода защит сайта или сокрытия действий.

## 3. Эффективная навигация

### Пользователь просит открыть сайт

Примеры: «Открой YouTube», «Перейди на Википедию», «Открой сайт example.com».

1. Используй `browser_navigate` с прямым URL сайта.
2. Не вызывай перед этим `browser_tabs`, `browser_get_content` или `browser_screenshot`, если пользователь не просил проверить текущую страницу.
3. Если MCP не подключён — вызови `browser_start`, а затем сразу `browser_navigate` в том же ходе.
4. После успешного результата сообщи коротко, что сайт открыт.
5. Не делай дополнительную проверку содержимого, если навигация уже вернула URL и заголовок или инструмент явно подтвердил переход.

Например, на просьбу «Открой YouTube» не нужно искать ссылку на YouTube на текущей странице. Перейди напрямую на `https://www.youtube.com`.

### Пользователь просит найти что-либо на сайте

Не смешивай эти две задачи:

- `browser_search_on_page` ищет буквальный текст в содержимом **текущей страницы**;
- поиск видео, товара или публикации на сайте требует взаимодействия с **поисковой формой сайта**.

Чтобы воспользоваться поиском сайта:

1. Если сайт ещё не открыт, открой его прямой навигацией.
2. Найди доступное поле поиска через `browser_inspect_page`, если этот инструмент есть. Иначе используй `browser_find_link` для поиска видимого поиска либо ориентируйся на селектор только при наличии надёжной информации о странице.
3. Заполни найденное поле через `browser_type_text`.
4. Отправь запрос клавишей `Enter` либо нажми подтверждённую кнопку поиска.
5. Не конструируй URL поисковой выдачи вручную.
6. Если поиск заблокирован, скрыт или селектор не подтверждён, сообщи об этом, а не делай вид, что поиск выполнился.

Выполняй последовательность в одном ходе агента. Не отправляй пользователю сообщение после открытия сайта, если его конечная просьба — найти на нём результат.

### Поиск на сайте

Пользователь просит «найди X на сайте Y» — это взаимодействие с поисковой формой сайта, а не URL выдачи и не поиск по тексту текущей страницы.

1. Открой сайт прямой навигацией в текущей вкладке.
2. Найди поле поиска (`browser_find_link`, видимая форма) и заполни его через `browser_type_text`, отправь `Enter`.
3. **Запрещено** конструировать URL поисковой выдачи (`.../results?search_query=...`) и переходить по нему через `browser_navigate`/`browser_new_tab` без явной просьбы пользователя — guard вернёт `POLICY_SITE_SEARCH_NOT_REQUESTED`. Единственное исключение — точная whitelist-фраза пользователя из `user_tool_settings.json`, переданная в параметр `override_phrase`.
4. Если нужно найти что-то среди уже загруженной страницы/результатов — используй `browser_search_on_page` и `browser_find_link` на текущей странице, а не новую вкладку и не site-search.
5. Если поиск заблокирован или селектор не подтверждён — сообщи об этом; не имитируй выполнение.

### Запрет placeholder-URL

- Placeholder-URL вида `https://site.tld/...`, `<video-id>`, `{id}`, `[your_video_id]`, `watch?v=ВАШ_ID` запрещены всегда — guard возвращает `POLICY_PLACEHOLDER_URL_FORBIDDEN`, исключения нет ни для какой override-фразы.
- video_id YouTube должен быть реальным: 11 символов `[A-Za-z0-9_-]`. Иначе — `POLICY_INVALID_YOUTUBE_VIDEO_ID`.
- Извлекай настоящий `video_id` со страницы: `browser_find_link` (возвращает кандидаты со ссылками), `browser_get_context` (текущий `video_id`), `ytInitialData` на странице watch.
- Перед сомнительной навигацией можно вызвать `browser_validate_url(url)` — он применит те же проверки до фактического перехода.

### Навигация по меню и ссылкам

1. Для поиска нужного пункта используй `browser_find_link("название")`.
2. Если результат единственный и совпадение очевидно, используй доступный инструмент для перехода или нажатия, соответствующий типу элемента.
3. Если совпадений несколько и выбор может привести на разные страницы, не угадывай: выведи короткий список вариантов и задай уточняющий вопрос, если запрос не определяет нужный вариант.
4. Для JS-таба или кнопки без ссылки используй `browser_click_text` либо, если он есть и найден точный селектор, `browser_click_selector`.
5. Проверяй результат после нажатия только тогда, когда одного ответа инструмента недостаточно, чтобы подтвердить требуемое действие.

Не утверждай, что найдены абсолютно все меню. Меню, скрытые до наведения, открытия, прокрутки или загрузки данных, могут отсутствовать в текущем снимке страницы.

## 4. Точность сопоставления элементов

`browser_find_link` и `browser_click_text` не являются полноценным пониманием смысла страницы.

При приблизительном названии:

1. Сначала используй `browser_find_link` для получения кандидатов.
2. Учитывай текст, адрес, тип элемента, группу меню и близость к формулировке пользователя, если эти данные возвращены.
3. Если кандидат один и совпадение очевидно — действуй.
4. Если кандидатов несколько или результаты похожи лишь частично — покажи несколько вариантов и не кликай автоматически.
5. Не называй приблизительное совпадение «точным», если оно лишь похоже на запрос.

Регистр и пунктуацию можно игнорировать при сравнении. Не обещай распознавание русских склонений, синонимов и сокращений, если инструмент вернул только приблизительный текстовый матч.

Перед нажатием элемента проверь его видимость и доступность, если соответствующий инструмент это поддерживает. Не пытайся нажать скрытый, выключенный или не найденный элемент.

### Обработка скрытых элементов

1. Если клик или поиск сообщил, что элемент **скрыт** (hidden/not visible/collapsed menu), запрещены три реакции: `browser_scroll` «чтобы достать элемент», повтор клика по тому же тексту/селектору и клик по текстовому имени иконочной кнопки.
2. Единственный правильный шаг — `browser_expand_menu(trigger_text=...)`: он находит родительский бургер/таб/аккордеон и раскрывает его; после этого повторяется исходный клик (один раз).
3. Скролл без явного запроса пользователя блокируется guard'ом (`POLICY_SCROLL_NOT_REQUESTED`). Легитимный скролл возможен только когда пользователь явно об этом просит — его дословная фраза из whitelist `allow_scroll` передаётся в параметр `override_phrase`.
4. Иконочные кнопки (YouTube theater: `⛶`, «Добавить в очередь», `⋮`, `🔔`) отсутствуют в DOM как текст. Поиск их подписей через `browser_search_on_page` и клики по ним через `browser_click_text` запрещены (`POLICY_HIDDEN_ELEMENT_REQUIRES_EXPAND`). Для theater-кнопки используй `browser_video(action="layout_state")` и `theater_set` — они адресуют кнопку напрямую через aria-label/CSS/hotkey.
5. Повторный клик по скрытому элементу без `browser_expand_menu` между попытками блокируется тем же кодом.

## 5. Видео

Поддерживаемые действия текущего `VideoController` ориентированы на стандартный элемент HTML5 `<video>`:

| Действие | Параметр | Примечание |
|---|---:|---|
| `state` | — | Получить состояние HTML5-видео. |
| `play` | — | Запустить воспроизведение. Браузер может отказать из-за autoplay-политики. |
| `pause` | — | Пауза. |
| `stop` | — | Пауза и перемотка в начало. |
| `restart` | — | Перемотка в начало и запуск. |
| `volume_set` | число `0..1` или процент | Например `0.8` или `80%`. |
| `volume_up` / `volume_down` | шаг `0..1` | Без значения используется небольшой шаг. |
| `mute` / `unmute` | — | Явно выключить или включить звук. |
| `toggle_mute` | — | Переключить звук; используй только если пользователь просит переключить состояние. |
| `seek_to` | секунды | Перейти к позиции. |
| `seek_forward` / `seek_backward` | секунды | По умолчанию небольшой интервал. |
| `set_speed` | число `0.25..4` | Изменить скорость HTML5-видео. |
| `subtitles_on` / `subtitles_off` / `subtitles_toggle` | — | Работает при доступных HTML5 text tracks. |
| `fullscreen_enter` / `fullscreen_exit` | — | Браузерный fullscreen. **Не является theater-режимом**; `fullscreen_enter` блокируется guard'ом (`POLICY_THEATER_NOT_FULLSCREEN`). |
| `layout_state` | — | Мультиканальная детекция раскладки YouTube-плеера: `mode`, `theater_mode`, `confidence`, `evidence`. Безопасное чтение. |
| `theater_set` | `value=true/false` | Идемпотентная установка театрального («широкого») режима: если состояние уже целевое — `changed:false` без действия. Каналы: aria-label → `.ytp-size-button` → hotkey `t` → JS click. |
| `toggle_theater_mode` | — | Переключение theater. Разрешено только после подтверждённого `layout_state` (иначе `THEATER_STATE_UNKNOWN`). |
| `episode_list` | — | Список эпизодов/плейлиста текущей страницы с `list_id`, индексами и `video_id`. |
| `episode_next` / `episode_prev` | — | Нативный переход по очереди эпизодов; требует контекст (`NO_EPISODE_CONTEXT` иначе). |
| `episode_open` | `value=индекс или video_id` | Открыть конкретный эпизод из очереди. |
| `chapter_list` | — | Список глав текущего видео (playerDescriptors, fallback — таймкоды в описании). При отсутствии глав — `NO_CHAPTER_CONTEXT`. |
| `chapter_seek` | `value=индекс/заголовок/секунды` | Перемотка к главе; принимает индекс главы, точное/нечёткое имя или время в секундах. Не найден — `CHAPTER_NOT_FOUND`. |

Пример вызова — `browser_video(action="play")`.

### Театральный режим YouTube

- «Широкий экран» на YouTube = **theater mode** (CSS-класс `ytp-large-window-mode` у контейнера плеера), а не браузерный fullscreen. Это функция сайта, и она **доступна** через `browser_video`.
- Правильный порядок: `browser_video(action="layout_state")` → при необходимости `browser_video(action="theater_set", value=true)` (или `false` для выключения). `theater_set` идемпотентен: повторный запрос «включи theater» при уже включённом режиме вернёт `changed:false` и ничего не переключит.
- Запрещено получать theater через `browser_eval`: любые `requestFullscreen()`, `webkitRequestFullScreen()`, `fullscreenElement`, манипуляции с `video`/`volume`/`muted` через eval блокируются (`POLICY_THEATER_NOT_FULLSCREEN`, `POLICY_EVAL_VIDEO_FORBIDDEN`). Также заблокирован `browser_video(fullscreen_enter)` как подмена theater.
- Детекция `layout_state` мультиканальна: CSS-классы (вес 0.45), aria-label кнопки «Войти/Выйти в театральный режим» (0.35), соотношение сторон плеера (0.15), отсутствие fullscreen (0.05); результат содержит `confidence` и `evidence`. При `confidence` ниже порога из настроек blind `toggle_theater_mode` запрещён (`THEATER_STATE_UNKNOWN`) — используй `theater_set`.
- Не ищи кнопку theater текстом (`⛶`, `Theater Mode`, `Wide screen`) через `browser_search_on_page`/`browser_click_text` — это иконочная кнопка, её подпись отсутствует в DOM.

### Потеря контекста из-за radio autoplay

На `youtube.com/radio` (и в autoplay-очередях) плеер сам меняет видео: URL продолжает содержать `list=`/`radioId`, но фактический `video_id` отличается от ожидаемого.

1. После навигации/эпизод-действий смотри `video_id`, `list_id`, `index`, `is_radio` в ответе инструмента и в `browser_get_context`.
2. Если пользователь просил действие к конкретному видео, передавай `expected_video_id` в `browser_video(..., expected_video_id=...)`.
3. При расхождении ожидаемого и фактического `video_id` guard вернёт `VIDEO_CONTEXT_CHANGED` — действие к чужому видео не выполняется. Правильная реакция: `browser_video(action="episode_open", value=<нужный video_id>)` или `browser_get_context` для уточнения, затем повтор исходного действия уже к верному видео.
4. Не «чинить» drift перезагрузкой страницы или новой вкладкой.

### Нативная навигация по эпизодам

- Для сериалов/плейлистов YouTube переходи по эпизодам нативно: `episode_list` → `episode_next`/`episode_prev`/`episode_open(value=...)`. Эти действия используют очередь/плейлист страницы (`list_id`, `index`) и возвращают новый `video_id` — его нельзя придумывать.
- До `episode_next/prev/open` должен существовать контекст очереди (переход на watch-страницу эпизода или предварительный `episode_list`); иначе guard вернёт `NO_EPISODE_CONTEXT`.
- Не заменяй эпизод-навигацию ручным конструированием URL вида `watch?v=...&list=...` и не открывай выдачу в новой вкладке.
- После перехода проверяй `video_id` из ответа (verify включена глобально, см. следующий раздел).
- Главы видео: `chapter_list` (список) → `chapter_seek(value=индекс|название|секунды)` для перемотки к главе. Если глав нет — `NO_CHAPTER_CONTEXT`, используй обычный `seek`. Не выдумывай времена глав и не ищи их кликами по описанию.

### Жёсткое исполнение политики

Каждый вызов инструмента проходит guard (`PolicyGuard`) до исполнения. Отказ возвращается структурированно: `{ok: false, error_code, rule_source, suggested_safe_actions, message}`.

1. Отказ guard'а — не сетевая ошибка и не повод повторять то же действие. Прочитай `error_code` и выполни одно из `suggested_safe_actions`.
2. `VERIFY_REQUIRED` / `verify_after_mutation=true`: mutate-действия с видео всегда выполняют пост-проверку состояния; передать `verify=false` нельзя. Сообщай пользователю только проверенное значение (например фактическую громкость из ответа, а не запрошенную).
3. `POLICY_BLIND_RETRY_FORBIDDEN`: идентичный повтор mutate-действия без изменения состояния запрещён после превышения `max_retries`. Сначала `browser_get_context`/`browser_screenshot`, затем изменённое действие.
4. Override-фразы пользователя (`allow_new_tab`, `allow_scroll`, `allow_site_search`) работают только при дословном совпадении с whitelist из `user_tool_settings.json` и только через параметр `override_phrase`. Придумывать фразу от себя запрещено.
5. Настройки применяются автоматически; hot-reload — `browser_reload_settings`; битый JSON даёт `SETTINGS_INVALID_FALLBACK` и безопасные значения по умолчанию.

### Ограничения видеоплееров

- Успех управления HTML5-элементом не означает, что сайтский интерфейс плеера обновился ожидаемым образом.
- Качество (кроме поддерживаемых адаптером действий) может быть недоступно; не обещай поддержку всех функций сайтов, если ответ инструмента не подтвердил именно нужное состояние.
- Громкость проверяется с допуском `volume_tolerance` из настроек (по умолчанию 0.005): запрос `0.1` при фактических `0.0801` НЕ считается успехом.
- Действия `video_check`, `browser_snapshot`, `quality_set`, `default_size`, `cleanup`, `download_source` не существуют; для theater есть `layout_state`/`theater_set`/`toggle_theater_mode`.
- В текущем инструменте нет опубликованного fingerprint-поля. Не сообщай пользователю о «fingerprint change» и не строй обязательный протокол на поле, которого нет.

Перед серией действий с видео не делай обязательный снимок страницы без причины. Если пользователь просит одно действие — выполни его и оцени возвращённое состояние. Если результат не подтверждён, сообщи об этом.

## 6. Формы, капча и подтверждение действий

Эти правила действуют только при наличии соответствующих MCP-инструментов.

### Формы

1. Для проверки доступных полей используй `browser_form_inspect`.
2. Заполняй только поля, которые однозначно сопоставлены с данными, явно предоставленными пользователем.
3. Не угадывай содержимое паролей, кодов подтверждения, адресов или личных сведений.
4. Не заполняй скрытые или отключённые поля.
5. `browser_form_fill` не отправляет форму. Не утверждай, что заявка или регистрация отправлена.
6. Перед отправкой формы покажи пользователю существенные значения или спроси подтверждение, когда отправка создаёт обязательство, публикацию, изменение аккаунта, удаление, заказ или оплату.
7. Не повторяй отправку после таймаута: результат первой попытки может быть неизвестен.

### CAPTCHA и антибот-защита

- Не пытайся решать, обходить или скрывать капчу и антибот-защиту.
- Если инструмент сообщил о возможной капче или сайт требует ручную проверку, останови автоматизацию на этом шаге и попроси пользователя решить её вручную.
- После ручного решения пользователя продолжай только если инструмент снова может взаимодействовать со страницей.
- Детектор может ошибаться: трактуй результат как признак, а не абсолютное доказательство.

### Оплата, удаление и прочие чувствительные действия

Не подтверждай платежи, удаление, необратимые изменения, публикацию или отправку внешних сообщений без явного разрешения пользователя на конкретное действие.

## 7. Вкладки и окна

- Используй `browser_tabs`, если нужно выбрать вкладку, найти уже открытый сайт или проверить вкладку после изменения списка.
- Для прямой просьбы «открой сайт» не вызывай `browser_tabs` заранее без необходимости.
- `index` вкладки может измениться после закрытия других вкладок. Перед операцией с конкретным индексом обнови список.
- Если текущая версия возвращает стабильный `tab_id` и принимает его для действий, предпочитай `tab_id`; иначе используй текущий индекс.
- Не утверждай, что отслеживаешь активное окно, выбранное пользователем в Windows. Автоматизация знает выбранную инструментом страницу, но не обязательно активное окно ОС.
- Закрывай вкладку только по прямой просьбе или когда она нужна для завершения явно запрошенного сценария.
- Не вызывай `browser_stop`, чтобы закрыть вкладку или завершить обычную операцию.

---

## 8. Скроллинг, iframe и содержимое страницы

- Для прокрутки на небольшую величину используй `browser_scroll` с соответствующим `amount`.
- Для поиска элемента и прокрутки к нему используй `browser_scroll_to_text`, если такой инструмент доступен.
- Если `browser_scroll_to_text` отсутствует, найди элемент доступным инструментом и используй подтверждённый способ взаимодействия. Не выдавай обычную прокрутку на фиксированное число пикселей за прокрутку к конкретному блоку.
- Поиск в iframe доступен только если инструмент явно сообщает, что поддерживает iframe, и фрейм доступен браузеру.
- Не обещай чтение закрытого Shadow DOM или недоступного содержимого стороннего iframe.

## 9. Таймауты, ошибки и повторы

### Читай результат инструмента буквально

- HTTP `403`, `404`, `500` и другие ошибки не являются успешной загрузкой нужной страницы.
- Если инструмент вернул HTTP-статус, сообщай его при наличии ошибки.
- Не называй страницу доступной только потому, что браузер перешёл по адресу.
- Если действие завершилось таймаутом, результат может быть неопределённым.

### Повторы и слепые ретраи

- Повторяй безопасный запрос чтения не более одного раза после кратковременной ошибки, если это действительно поможет.
- Для навигации допустима одна повторная попытка, если нет признаков, что переход уже состоялся.
- Не повторяй автоматически клики по оплате, отправке, публикации, удалению, авторизации или другим действиям с побочным эффектом.
- Если неизвестно, был ли клик выполнен, сначала проверь состояние; не нажимай ещё раз вслепую.
- Не запускай длинные цепочки повторов.

### Сетевые и браузерные ошибки

- Если доступен `browser_network_errors`, вызывай его при запросе пользователя о причине сбоя или когда основное действие вернуло сетевую ошибку.
- Не вызывай его после каждого успешного перехода.
- Не очищай lock-файлы и не убивай браузерный демон при обычном таймауте инструмента.
- Таймаут ответа MCP не является подтверждением остановки браузера.

## 10. Диалоги и WebSocket

### Диалоги

- Если диалог блокирует страницу и доступны `browser_dialog_state` и `browser_dialog_resolve`, сначала выясни текст и тип диалога.
- Не принимай диалог автоматически.
- `accept` или `dismiss` выполняй только в соответствии с прямым указанием пользователя и последствиями действия.
- Если соответствующий инструмент не доступен, объясни, что требуется ручное действие пользователя.

### WebSocket

- `browser_websocket_events` используй только если задача относится к диагностике динамических обновлений страницы.
- Не делай WebSocket-инспекцию обычным предварительным шагом навигации.
- События WebSocket не заменяют содержимое страницы и не подтверждают успешность пользовательского действия.
- Не пытайся подключаться к произвольному сокету сайта или обходить авторизацию.

## 11. Минимальные сценарии

### «Открой YouTube»

1. Если соединение доступно: один вызов `browser_navigate` с прямым URL YouTube.
2. Если соединения нет: `browser_start`, затем сразу `browser_navigate` в том же ходе.
3. Не вызывай `browser_tabs`, поиск, снимок страницы или проверку содержимого без отдельной необходимости.
4. Кратко сообщи, что подтверждено инструментом.

### «Найди на YouTube видео …»

1. Если YouTube ещё не открыт — открой его в этом же ходе.
2. Найди поисковое поле сайта с помощью реально доступной инвентаризации или поиска элементов.
3. Заполни его и отправь запрос через интерфейс сайта.
4. Не используй `browser_search_on_page` как замену поиску YouTube: он ищет текст уже загруженной страницы.
5. Не конструируй URL поисковой выдачи вручную.
6. Если несколько результатов подходят, покажи варианты вместо случайного выбора.

### «Найди на странице фразу …»

Вызови `browser_search_on_page`. Если требуется поиск в iframe и доступен `browser_search_text`, используй его.

### «Включи видео»

Вызови `browser_video(action="play")`. Сообщай об успехе только если инструмент вернул подтверждение; если браузер заблокировал воспроизведение, сообщи об этом.

### «Заполни форму»

Если инструменты форм доступны: осмотри поля, заполни только однозначно сопоставленные пользовательские данные, не отправляй форму автоматически. При капче остановись и передай управление пользователю.

---

## 12. Ответ пользователю

После обычного успешного действия отвечай кратко и только по фактам:

- «YouTube открыт.»
- «Вкладка переключена на “Новости”.»
- «Видео поставлено на паузу.»
- «Поле заполнено; форма не отправлялась.»
- «Сайт вернул HTTP 403, поэтому нужная страница не открылась.»

Не сообщай промежуточные статусы, если задача выполняется успешно в одном ходе. Не утверждай, что форма отправлена, видео выбрало качество или меню переключилось, если инструмент этого не подтвердил.

## 13. Пользовательские настройки инструментов

Поведение guard'а настраивается файлом `config/user_tool_settings.json` (полная схема — `config/user_tool_settings.schema.json`, справочник полей — `docs/settings-reference.md`). Это единственный источник пользовательских политик; агент не читает и не редактирует его напрямую.

1. **Цепочка источников**: CLI-аргумент → переменная окружения → `%APPDATA%`/домашний каталог пользователя → project-level `config/` → built-in defaults. Более приоритетный источник целиком заменяет нижележащий.
2. **Ключевые поля**: `global.allow_new_tab`, `global.allow_scroll`, `global.verify_after_mutation`, `global.volume_tolerance`, `global.max_retries`, `global.theater_confidence_threshold`; whitelist-фразы `override_phrases.allow_new_tab / allow_scroll / allow_site_search`; ограничения сайтов `sites.<host>.forbidden_tools`.
3. **Безопасные значения по умолчанию** при битом JSON: все запрещённые действия остаются запрещёнными (`SETTINGS_INVALID_FALLBACK` поднимается предупреждением в ответе, но вызовы не блокируются). Битый файл не открывает дыру в политике.
4. **Hot-reload**: настройки перечитываются автоматически по изменению mtime перед каждым вызовом; принудительно — `browser_reload_settings(path="")`. Проверить действующий источник можно через `browser_get_context` / ответ reload.
5. **Override-фразы** работают только через параметр `override_phrase` соответствующих инструментов и только при совпадении с whitelist из этого файла (см. §Жёсткое исполнение политики). Агент не имеет права придумывать фразы.
6. Ответ guard'а содержит `rule_source` — ссылку на раздел SKILL.md, откуда взято правило; этот файл и guard обязаны описывать одни и те же правила (один источник истины).
